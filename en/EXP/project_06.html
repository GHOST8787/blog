LINE Message Analyzer:
A Two-Day Deep Refactor Log

Open Source Refactoring Frontend
2026.02.23 BY GHOST_1010

A deep refactor of the open-source tool line-message-analyzer — both the underlying architecture and the frontend. The original gave basic message stat visualization, but years of low maintenance left hardcoded limits and scaling ceilings. The job: a modern stack, fixed logic bugs, and code that holds up to maintenance.

Heya

line-message-analyzer is an open-source web tool: a user uploads an exported LINE chat .txt file, the tool generates stat charts — messages per member, sticker ratio, peak activity hours, etc. The original had two main limitations: it only handled exactly two-person chats (broke on group chats) and the UI broke on mobile. This project documents the refactor: rebuilt the architecture to support any number of members, switched to a responsive UI, removed outdated dependencies, contributed the changes back to the original project's community.

# UI Refactor and Render Optimization

The original leaned hard on Bootstrap, which made the components flat and coupled. Responsive behavior was missing. The refactor:

  • Style system migration: moved the whole project to Tailwind CSS. Utility-first separates style from structure logically.
  • Responsive grid: introduced Flexbox layout that allocates container width by breakpoint. The mobile rendering breakage is gone.

# Core Breakthrough: Decoupling Data from Rendering

The most damaging architectural flaw: render nodes were hardwired to a fixed data count. The system declared exactly two DOM canvases, memberCanvas1 and memberCanvas2. Any group with more than two members got truncated at render time.

Fix: switch to data-driven rendering.

  • Dynamic registration in the parser Rewrote analyze.js. While scanning text, the system extracts unique entity names and dynamically allocates a stats array in the state pool. The member-count ceiling is gone.
  • Render layer maps data to DOM The frontend receives the data object and loops over it, dynamically creating card containers and Canvas instances. Combined with the flex-wrap grid above, an N-member dataset renders smoothly.

# Working with AI Agents: Boundaries and Discipline

This refactor leaned hard on AI assistance. The process surfaced both its strengths and its failure modes in software engineering:

Where productivity went up

Prototyping, regex reasoning, and cleaning redundant code. AI cuts the time on these significantly.

Where it breaks things

AI does not hold the global state well. It happily fixes a local bug while destroying the broader structure. It will also slip in unauthorized "improvements."

Collaboration rules

The developer owns architectural decisions. Tasks get split into atomic commits with rollback points. No giant AI-driven rewrites of core logic.

# Tech Debt and Roadmap

The refactor settled the underlying skeleton. The next round of optimization targets these known edge cases:

Issue #2 & #4: edge cases in unstructured text

  • Name string fragmentation: entity names with spaces (like "John Doe") trip the parser pointer. I added a Tab-separated mechanism as a first pass. Long term, dynamic affix analysis is needed.
  • Timestamp confusion: the English export format (AM/PM) does not match the existing regex. An adaptive locale detector that switches the matching logic is the right fix.

Extension Dimensions

1. Data export module A standardized API for JSON and CSV export. Makes downstream data mining easy.
2. Higher-dimension insights Time-series analysis. Compute per-node active hours, response latency, and similar dynamic metrics.
3. Cross-dataset comparison Support multiple data inputs. Run parallel comparison visualizations across groups.
4. Interaction upgrade Canvas/SVG event listeners. Drill-down on data points, exploratory timeline scrubbing.
