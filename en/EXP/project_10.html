From Unstructured Text to a Queryable Table:
Automating an Escape Room Rating List

AI & Automation Web Scraping Claude CoWork
2026.04.20 BY GHOST_1010

Taking a long-form blog review and using AI to turn it into a sortable, filterable structured table. A record of the process and the method.

# The Problem: Complete Information, Hard to Query

When picking an escape room, leaning on a credible long-term review list is the efficient path. In Taiwan's escape room scene, Roger Song's "Spoiler-Free Escape Room Review and Recommendation List" is the reference of choice: broad coverage, a rating system, frequently updated, no spoilers.

The linear blog format does not match how the list actually gets used. Real queries are multi-condition filters:

  • Rating S, party of 4 or fewer, specific city
  • Not played yet, rating A or above, medium difficulty
  • List every S-rated room first as a shortlist

The blog UI only supports Ctrl+F keyword search. Cross-filtering by "rating + city + party size" simultaneously is not on the table. Each query takes 1–2 minutes of scrolling.

# Approach: Hand the Extraction to AI

Manual copy-paste into a spreadsheet works. This time I handed the whole thing to Claude CoWork driving a Chrome session. No code got written. The work concentrated on one thing: defining the target schema clearly. AI handled the extraction and the output.

Step 1: Feed in the source

Paste the blog URL into Claude CoWork. The AI fetches the full page and parses the HTML. The original post is long, but it sits inside a single LLM parse window.

Step 2: Define the schema and extract fields

Pre-defined nine fields per room:

Field Description
StudioOperating team
AddressCity and location
ThemeRoom title
RatingS / A / B / C / D / –
Party sizeRecommended player count
DurationPlaytime
GenreTheme category
StatusOpen / archived
NotesExtra info

The rating system follows the original author's standard verbatim. The AI moves data. It does not make judgment calls.

Step 3: Output to Google Sheets

The AI writes results straight into Google Sheets. First row is the header. Each subsequent row is one room. Sheets handles sorting and filtering natively. No frontend needed.

The whole run took 3–4 prompts. The AI did the rest on its own.

# Outcome: a Two-Layer Query Interface

The final artifact is a plain Google Sheet, structured in two layers:

Sheet tabs (by region)

Greater Taipei Taichung Taoyuan / Zhongli Hsinchu / Changhua / Nantou Tainan Kaohsiung Yilan / Pingtung / Overseas + Source info

Schema (shared across tabs)

Studio
Address
Theme
Rating
Party
Duration
Genre
Status
Notes

Typical query path

  1. Switch to the target region tab
  2. Use "Data → Create a filter"
  3. Filter rating to S / A, status to "Open"
  4. Narrow by party size or genre
  5. Scan the theme column. Pick.

From opening the sheet to landing on a venue: under one minute.
