Closing the Gap in Chrome's Synced Tabs:
Device Tabs Opener

Engineering Chrome Extension Open Source
2026.04.20 BY GHOST_1010

A Chrome Extension that solves one thing: opening tabs from other devices in batch. Covers Manifest V3, vanilla JS implementation, MIT licensing, and the Web Store submission flow.

Heya

A Chrome Extension is a small add-on installed inside the Chrome browser. After installation, an icon appears in the toolbar; clicking it triggers a specific function. This project's function: take the tabs currently open on a phone running Chrome and, with one click, open them all on the desktop browser. Manifest V3 is the technical specification Chrome has required for all new extensions since 2024. This project was built to that spec, passed Chrome Web Store review, and is live.

# The Problem: Feature Exists, UX Path Broken

Chrome's cross-device tab sync already pushes open tabs from iPhone / iPad up to the desktop. The access path:

Chrome → History → Tabs from other devices

The list only supports opening one tab at a time. 10 tabs to clear means 10 clicks. After each click the focus jumps away from the list, so you scroll back in. For "drop everything I had open on my phone onto the desktop right now," the friction is too high.

Chrome already implemented the sync. What's missing is the batch action layer.

# Implementation: Three APIs, a Minimum Loop

Stack

  • Manifest V3: Chrome requires V3 for new extensions since 2024. Service Worker replaces background pages. Permission model is stricter.
  • Vanilla JavaScript: no framework, no bundler. One HTML file plus one JS file. A few hundred lines total.

File layout: 

device-tabs-opener/
├── manifest.json     # permissions and entry points
├── popup.html        # UI shown when the toolbar icon is clicked
├── popup.js          # interaction logic and batch open
├── background.js     # Service Worker (required in V3)
└── icons/            # toolbar icons

Core APIs

API Purpose
chrome.sessions.getDevices() Returns all synced devices and their tab lists as structured objects (device name, title, URL, last used).
chrome.windows.create({ url: [...] }) Opens a URL array in a new window. I chose a new window over the current one to avoid disrupting the existing workflow with a flood of tabs.
popup UI Lists every device and tab with a checkbox per row. Three buttons: select all, clear, open selected.

Click the icon, click open, and the new window appears in 2–3 seconds.

Permissions and Privacy

manifest.json declares only two permissions:

  • sessions: read synced tab lists from other devices
  • tabs: open selected tabs in a new window

No storage, no activeTab, no host_permissions. All data stays local. Discarded after execution. No backend. No third-party tracking. No user data collection. Source code is open on GitHub under MIT.

# The Submission Flow

First time taking a Chrome Extension all the way through Web Store submission. Key checkpoints:

1. License: MIT

Personal tool. I wanted others to fork and modify freely, so MIT — keep the copyright notice and you can use, modify, and redistribute commercially.

2. Chrome Web Store developer account

One-time 5 USD registration fee. After that, extensions can be created.

3. Packaging and assets

Zip the directory and upload. The extra assets:

  • Extension icon (128×128)
  • Promo image (440×280)
  • Store screenshots (1280×800)
  • Listing description and permission justification

The assets took longer than the code did. The code was finished early.

4. Review

Single-purpose, minimal permissions, no extra data collection — approved on the first pass. The only wait was queue time.

5. Install experience after launch

Users click "Add to Chrome" from the Web Store page. No developer mode, no zip download.
