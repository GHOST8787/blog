Device Tabs Opener v2.2.0:
UI Redesign, Bilingual, and Per-Tab Checkboxes

Engineering UI Redesign Chrome Extension
2026.05.19 BY GHOST_1010

v2.1.0 covered the functional ground: batch-opening synced tabs across devices. v2.2.0 reworks the visuals and interaction layer. The whole UI gets redesigned, bilingual switching ships, and "open everything from one device" splits into per-tab checkboxes. Currently in Chrome Web Store review.

Heya

Device Tabs Opener is a Chrome Extension (a small add-on inside the Chrome browser). The function: take the tabs open on a phone running Chrome and open them all on the desktop browser with one click. v2.1.0 shipped the core function and the Chrome Web Store listing; v2.2.0 is a full pass on visuals and interaction. Background and basic usage are covered in P11, the v2.1.0 log.

# Starting Point: Two Gaps from v2.1.0

v2.1.0 prioritized getting the function working. The interface ran on a saturated dark palette with one "open all" button per device. After using it for a while, two gaps surfaced:

  • 1. Visual tone vs Chrome Web Store store-page tone — dark and saturated reads fine for a brief popup, but on a 1280×800 promotional screenshot the whole thing leans into game-demo territory, drifting from the "daily productivity tool" position.
  • 2. Interaction unit too coarse — synced tabs often include a dozen noise pages. "Open everything from this device" opens the noise too. In practice I had to close the noise on my phone first, then open the rest with the extension. The filtering cost gets pushed back to the user.

# Palette: Editorial Sunset Coral

The palette goal: let the popup and the store-page promotional shots share the same design tokens, with overall feel closer to print magazine / Editorial. Four color blocks, each with a role:

  • Cream #faf3e8 — background and card surface, mimics printed paper.
  • Warm orange #d65a3a — primary, CTA buttons + focus text + chip borders.
  • Terracotta / purple / yellow — three accent colors, used in logo blocks and promo visuals. Keeps a single orange from getting heavy.
  • Black / gray — body and secondary text, carries information density through contrast.

# Interaction: Give Filtering Back to the User

The single batch button breaks into three layers of control:

  • Per-tab — each tab row gets a checkbox, unchecked by default. The user checks the ones to open.
  • Per-device — the header offers a "select all / clear" toggle. The original batch flow still covers in one click.
  • Global CTA — the bottom button text updates live: "Open 3 selected tabs". Disabled when no tabs are checked.

Outcome: a sync of 30 tabs can now skip 27 noise items and open just the 3 working tabs. No need to close noise on the phone first.

# i18n: Two messages.json Files + One Toggle

Chrome Extension supports the _locales/ directory pattern natively: 

_locales/
  zh_TW/messages.json   ← default
  en/messages.json      ← toggle target

manifest.json declares default_locale: "zh_TW" and the storage permission. The top-right toggle writes to chrome.storage.local. On every popup open, the user's stored choice takes priority; if missing, it falls back to chrome.i18n.getUILanguage().

# Accessibility: Two Media Queries

  • :focus-visible — keyboard tab navigation shows an orange focus ring, mouse clicks keep the default styling.
  • prefers-reduced-motion: reduce — when the system flag is on, all transitions drop to 0s.
  • System high-contrast mode — handled by the browser's native styles, no CSS override.
