Part 1 set up the macro boundaries and the context rules. This part zooms into execution: how to design tools an agent picks correctly, the actual job of subagents, the engineering meaning behind a few high-frequency commands, and the three evolutionary stages every developer goes through.

Tool Design: Make Claude Pick Right

A tool built for an agent is structurally different from an API built for humans. Humans optimize for feature completeness. Agents optimize for low misclassification rate.

Case study: how the AskUserQuestion mechanism evolved
  • V1
    Markdown convention: prompt the model to ask in a specific format
    Claude ignored it and answered anyway.
  • V2
    Flag parameter: add an --ask flag to an existing tool
    The flag kept getting skipped.
  • V3
    Dedicated tool: wrap it as a standalone AskUserQuestion tool
    Stable. Calling it triggers a system interrupt.
When not to add another tool
  • The local shell already handles it reliably
  • The model only needs static knowledge, no interaction
  • A skill workflow constraint fits better

Subagents: Isolation Matters More Than Parallelism

The real value of a subagent is contamination isolation, not raw parallel compute. When scanning a large codebase, hand it off to a subagent. The main thread only takes back the summary. The global context stays clean.

Configure subagents with explicit limits:
tools Restrict what it can use. No global access.
model Use Haiku for exploration to save cost.
maxTurns Cap the step count so it stops looping.
worktree Isolate the filesystem when files get touched.

The Engineering Behind a Few High-Frequency Commands

These commands all serve one purpose: manage context actively. Do not wait for the system to handle it for you.

/insight

Has Claude surface the things you keep repeating but never wrote into the contract. The best way to iterate on CLAUDE.md.

/rewind

Reset back to a specific checkpoint and re-summarize. Use when the agent went sideways but the earlier consensus is worth keeping.

--fork

Branch a parallel universe from the current context. Good for A/B architectural comparisons without polluting the main session.

Double-tap ESC

Jump back to the last input and edit it. When Claude drifts off course, rewriting the last message is faster than starting a new session.

Three Stages and One Verification Rule

1. ChatBot stage

Treat it as a chat partner and rely on your own brain to patch missing context. Result: the context turns into a mess.

2. Configuration stage

Start writing CLAUDE.md and plugging in external tools. Result: the rules grow long and the model selectively ignores them.

3. Engineering stage

The question shifts from "how do I use this feature" to "how do I design a system where the agent operates and verifies itself under explicit constraints."

The Verification Loop: the Hard Rule

"Claude says it's done" never equals done. If you cannot say exactly "which script has to pass for this to count as complete," the task is not ready to hand off to an agent for autonomous execution. The acceptance bar gets locked in at the prompt or skill layer. Not after.
