一個論壇用問卷跟你告別，
暫停的方式，比暫停本身更值得談

Thinking Platform Communication
2026.06.12 BY GHOST_1010

我平常會看一個匿名的社群論壇。某天點進去，整個論壇不見了——看板、討論串全部進不去，首頁被換成一張頁面：一句「沈澱、喘息中」，底下八個問題、一個留言框，最後一行小字連回它的主站。使用者無法再瀏覽原本的內容，所有入口都被導向同一份問卷式的頁面。讓我在意的，是它選擇收掉自己的這個方式。

它留下的八個問題，原話大概是這樣：

  1. 你是什麼時候發現這個平台不見的？那一刻，你的第一個念頭是什麼？
  2. 一個地方「一直都在」，你覺得是預設值，還是成本？
  3. 一個沒有廣告、不用實名、沒有演算法推播的地方，你覺得它靠什麼活著？
  4. 它收的錢少到不像話。你覺得是很傻、很佛、不會賺，還是不能賺？
  5. 大家平常也都會用別的平台。它們的「穩定」，跟它的「穩定」，是同一種東西嗎？
  6. 如果開這個地方的人有名有姓、有臉、天天現身跟大家搏感情，你還會像現在這樣說話嗎？
  7. 這次的事，你是自己發現的，還是從別人那裡聽說的？
  8. 如果想對這個地方說一句話（對此處，不是對任何「人」），就留在這裡。

下面一條一條談，文末附一段技術觀察——我把這張頁面的原始碼翻出來，看它到底怎麼把一個好好的論壇換成這個樣子。

# 一直都在，不等於要被供著

第二題：一個地方「一直都在」，你覺得是預設值，還是成本？

一個東西一直都在的時候，沒有人會去想它為什麼在；等它不在了，有需要的人會去找下一個。東西大多帶有替代性，而替代品的價值，是在被需要的當下才被選擇，不需要使用者預先承諾去維持。所以回頭問使用者「我一直都在，你覺得是預設值還是成本」，這道題本身就有點微妙。

# 一個平台能不能靠興趣活下去

第四題：它收的錢少到不像話，你覺得是很傻、很佛、不會賺，還是不能賺？

這問題讓我想到 Wootalk，一個匿名隨機配對的聊天網站。

它的運作方式是這樣：創辦人說過，這是他閒暇時做的，本來只想弄一個「24 小時都找得到人聊天」的地方，到今天都沒有商業化。它完全免費、不用註冊，頁面上沒有廣告，也沒有把使用者的對話數據拿去賣；伺服器從比較貴的雲端搬到便宜很多的主機，把成本壓下去，就這樣一直開著。它活下去的方式，是繼續開著、繼續有人用。

這說明一件事：一個幾乎不收費的地方，照樣能年復一年地開下去。一個平台要不要賺、賺不賺得到，屬於經營者的選擇與本事。回到那道題的設計——有商機的時候，經營者通常不會把它交給使用者一起想；沒有商機的時候，把它描述成一種犧牲或奉獻，會把討論從經營策略，帶往情感認同的方向。把一個經營者自己的選擇，包裝成一道讓使用者來掂量的題目，是這道題真正的問題。

# 暫停的方式，與使用者的選擇權

這次的做法，是把整個論壇功能換成一張新頁面，影響的範圍比單純發布公告大得多。

在論壇裡發一篇文，跟把整個公共空間換成一份問卷，是兩件事。發一篇文，使用者自己決定要不要點進來、要不要回；把整個門面換掉，每一個來的人都先撞上這八個問題，才找得到其他出口。原本能回話的地方，變成一個只能單向投遞的信箱；原本發文的地方，變成它想問的八個問題。使用者被放到一個比較被動的位置，這也是我對這種溝通方式有疑問的起點。

# 問題的引導性，與被留下的資料

八個問題的句型幾乎一致：是預設值還是成本、很傻很佛不會賺還是不能賺、它的「穩定」跟別處的「穩定」是不是同一種。這種句型看起來開放，選項本身已經把立場放了進去——問你是預設值還是成本的當下，「這個地方值得被珍惜」這個前提，已經先替你決定好了。

我個人對開放的匿名空間沒有意見。如果只是擺一個空白的格子、沒有任何引導，誰想說什麼就說什麼，我認為完全沒問題。需要分開來看的是引導式的問法：題目先替你把方向圈好，你只能在它畫的框裡走；你寫下的東西，又收進它的後台留底。一個把使用者圈進預設立場、再把回答留起來的設計，跟一個單純開放的空間，是兩種不同的東西。

# 論壇的公共性：公版與個版

退一步看這個地方的定位。部落格是個版，是你家的客廳：牆上掛什麼、訪客留言區擺幾個問題，全憑你高興，沒有人能說你錯。論壇是另一回事。論壇是公版，一旦它開放給大眾、長出一群固定來的人，它就帶上了公共性。

這個分法不是我自己編的。傳播學裡有個經典概念叫「公共領域」（public sphere，哲學家 Habermas 提出）：一個讓人放下身分、平等討論的公共空間，它的重量來自參與的人。社會學家 Oldenburg 講的「第三空間」（third place），說的也是這個——家與職場之外、讓人有歸屬感的聚會地，咖啡館、酒吧、論壇都算；這種地方的主角是來的人，開店的人比較像場地的看守。後來研究線上社群的學者還發現，待得夠久的成員，會對社群長出一種「心理所有權」，把它當成「我們的」地方，自發去維護它。

把這幾件事疊起來，話就清楚了：一個東西一旦被定義成論壇，它就預設了以使用者、以這群人的利益為先。把整個公共空間，換成一份以經營者處境為核心的問卷，是拿公版的位置，做個版的事。如果一開始就講明這是個人部落格、是經營者的個版，那以上全都不成立。個版跟公版，是兩種不同的承諾。

# 經營者的情緒，與索取的方向

做出一個這樣的地方，需要力氣，這點我沒有要爭，我也樂意用付費去支持它。需要分開來看的是另一件事：經營者自己的情緒，為什麼要整個平台的人一起承接。把論壇換成一張告別頁，讓每個路過的人先面對經營者的處境，對部分使用者來說，會帶來一種額外的情緒負擔——我姑且把它叫做「情緒房租」：你來用這個空間，順帶被收一筆沒打算付的情緒。

再往源頭看，價值有它自然流動的方向：別人主動來問你、需要你，你再開口。把一份問卷擺到所有人面前、等大家逐題回應，順序剛好是倒過來的。真要跟大家要東西，明著要就好——把「使用者付費」講出來，想支持的人會付，這條路乾淨、對等。

# 對等的做法，其實更省力

同樣一件事，有不收情緒租的做法，而且力氣更小。在論壇裡發一篇公告：這地方要暫停一陣子，原因是這些，想留話的留在下面。它本來就匿名，想回的人自然會回，想走的人正常走，每個人手上都還握著「要不要參與」這個選擇。

要收掉就說收掉，要更新就說更新，要問意見就開一份大家可以選擇填或不填的問卷。把決定講清楚，把選擇權留在對方手上，如此而已。

# 技術觀察：整個論壇如何被換成一張頁

除了溝通方式，技術上的實作也值得看。我把這張頁面的原始碼翻出來，幾項特徵剛好印證了上面的觀察。

一、全站攔截（catch-all routing）

我試了五個原論壇一定會有的網址——首頁、看板、最新討論、某篇文章、某個人的個人頁——回來的內容大小到位元組都一樣，都是 9956 bytes。不管打哪個網址，伺服器都回同一張頁面。原本的資料沒有消失，被一道吃掉所有路徑的規則統一導向這張頁。

二、邊緣運算部署

頁尾掛著 Cloudflare 的偵測程式，每個請求即時回源。配上「所有網址回同一頁，另有一個專收留言的 /api/leave」，它最接近一支跑在 Cloudflare 邊緣節點上的程式（Workers 或 Pages Functions 那一類）。我用 GET 去敲 /api/leave，回 405 Method Not Allowed：這個窗口只收 POST 進去的留言，讀不出東西來。

三、Honeypot 反垃圾機制

表單裡的「公司」欄位被 CSS 推到畫面外，真人看不到。自動灌廣告的程式會把它填上，後端就用這格有沒有被填，來辨識並過濾機器人。這招叫 honeypot，蜜罐。截圖裡那句「公司（請留空）」，是寫給機器人看的誘餌標籤。

四、完整的設計規格

CSS 註解裡留著一整套設計規格的痕跡：色票對應它自家的品牌紅、做了無障礙對比、輸入框字級至少 16px「避免 iOS 聚焦自動縮放」、按鈕點擊區至少 48px。還有這幾句，原封不動抄在這裡：「視覺方向 §5：深夜裡還亮著的一盞小燈」「六題之間的間距要大到讓每一題可以單獨被凝視」「頁尾主站一行：一扇安靜的側門」。連每道問題之間要留多大空白、好讓你逐題凝視，都被編號、寫進一份設計文件。

這四項疊在一起，是一份完整規劃過的設計成果——從全站攔截、機器人過濾，到每一處凝視間距，都被仔細處理過。

# 說回我自己

最後說回自己。我也做這些東西——寫網站、把它開放出來，你正在看的這一頁就是其中一個。做它的理由很簡單：想藉著它，遇到一群志同道合的人。

對這些東西的興趣，本身就是理由；不該因為自己的際遇，去抱怨任何人。

遇得到那群人是一種幸福，那就知足；遇不到，就把能力繼續往外推，一直往前看。做這些東西的動力，從頭到尾長在自己身上——這是看完那八個問題之後，我個人的想法總結。

Note

起點是一個我平常就在看的匿名社群頁面。文中對技術手法的描述，可由該頁面公開的原始碼逐項對照（catch-all、Cloudflare、honeypot、設計規格註解皆出自原始碼）。不點名平台、不針對經營者個人，只討論這種做法本身。
