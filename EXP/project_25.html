替 AI 影片摘要把關：
逐字稿對照與防 overfit 驗證

AI & Automation Verification Prompt Engineering
2026.06.25 BY GHOST_1010

yt-digest 把一條 YouTube 連結變成一份結構化的中文整理。處理一小時以上的訪談時，最需要盯的一件事是：模型會不會把講者沒講過的東西，寫得像真的一樣。這篇紀錄這一輪替輸出把關的三個動作——用通用規則收緊、用逐字稿逐句對照驗證、用跨類型樣本確認修法沒有 overfit——以及順手修掉的一個會重複收費的併發 bug。

這個工具的兩個世代與整體架構，寫在 YouTube 整理工具的兩個世代。這篇只談一件事：如何確保 AI 整理出來的一小時內容，每一句話都能經得起檢驗。

# 問題：一小時訪談一次吞，模型容易在三個地方滑掉

測試素材選用三集犯罪心理學的長訪談，每集時長介於 60 至 75 分鐘。把一整支字幕一次餵給模型，整理出來的結果在三個地方最容易出狀況：

  • 把不同主題綁進同一章。例如「日本少年A 的案例」和「犯罪基因（戰士基因、XYY）」是兩個獨立主題，模型圖省事會把它們塞進同一章，讀起來像在暗示因果。
  • 結尾用寒暄湊一章。節目尾聲的「主持人想再邀、母校趣事」這種閒聊，會被獨立成一個正式章節，佔掉一格實質內容的位置。
  • 數字與人名在轉換時失真。語音轉文字先輸出簡體，再轉繁體，專有名詞容易在這一步被換成同音的錯字。

# 動作一：規則寫成通用原則，這是防 overfit 的第一道

整理用的提示詞裡，給模型的是一組通用原則，白話講就是：

規則 1逐字稿沒出現的詞，禁止自創。

規則 2人名、數字存疑就標 [?]，留給人工確認。

規則 3講者明確否定的關係（例如「這兩件事對不上」），整理時要保留那個否定。

規則 4歸納寧少勿湊，沒把握的因果連結就留白。

這四條規則中，未包含任何針對特定影片的正確答案。全部都是「怎麼做才算誠實」的通則。模型換一支沒看過的影片時，靠的是同一套原則去自我約束。這一點是後面防 overfit 驗證的基礎：規則藏了特定影片的答案，換片就破功；規則只放通則，才有機會通用。

# 動作二：逐字稿逐句對照，這是「沒在編」的證據

規則寫得再好，仍要拿輸出去對原文。做法是把整理裡的每一個數字、每一句引述，拉回原始字幕找出處。以 EP182 為例，幾條對得上的內容：

整理寫的 時間戳 逐字稿原句
情殺佔整體殺人案件「快要破半」 01:41 「情殺其實在整體的殺人案件裡面來講，快要破半了」
財殺案：欠 160 萬賭債、買兇、詐領保險金 — 「我沒有殺人，是另外一個人殺的……我是給了李先生一筆錢」（數字與情節可回放查證）
「犯罪比較像是：弱點剛好被社會的痛腳踩到」 20:37 「犯罪比較像是一個，如果你有某一些弱點，剛好被社會的痛腳踩到，那犯罪其實就發出來了」

每一句引述都掛著原文時間戳，點下去直接跳到 YouTube 對應的秒數。讀的人可以自己核。

這套對照還有一個更重要的作用：它會誠實地標出哪裡還需要人工確認。同一批整理裡，中正大學被音譯後標成「中正[?]大學」、社會學家 Durkheim 被標成「圖爾幹[?]」——這些 [?] 就是模型在說「這個名字我從聲音猜的，請你查」。還有一個同音錯字：「鄭捷」（2014 北捷案）被語音轉文字先輸出成簡體「郑杰」、繁化成同音的「鄭傑」，對照逐字稿時抓出來，已改回「鄭捷」。驗證的價值，就在於把這種地方攤開來，變成一份可以查、可以修的清單。

# 動作三：換一支完全不同類型的影片，這才是真正的 overfit 測試

Overfit 用白話講，就是你的規則只在你調過的那幾支影片上有效，換一支就失靈。如果我只拿這三集犯罪訪談反覆調規則、調到輸出漂亮，很可能只是把這三集的答案間接寫進了規則，看起來通用、其實是在背答案。

測法是找一支內容差到極點的影片來跑同一套規則。我挑的是一支英文 VTuber 的閒聊八卦——主題、語氣、語言都跟學術犯罪訪談差很遠。結果一樣：整理沒有自創內容，存疑的外文人名照規則標上 [?]，把猜測留在問號裡。

同一套通用規則，能適用於「犯罪心理學長訪談」與「英文 VTuber 八卦」這兩種截然不同的內容。它收緊的是「模型愛把猜測寫成事實」這個通病，跟某一支影片的內容無關。這就是規則沒有 overfit 的證據。

# 動作四：一個會重複收費的併發 bug

把關之外，這一輪也修掉一個藏在背景排程裡的錢坑。處理影片的常駐程式每 5 分鐘巡一次佇列，把排隊中的影片撿起來跑。問題在於：一次重跑三支長片，整批可能跑超過 5 分鐘；這時下一次巡邏又啟動，把同一支還沒處理完、狀態還是排隊中的影片再撿一次，於是同一支影片被處理兩次，付了兩次下載與 AI 的錢。

修法是加入一道鎖定機制：當上一輪處理尚未完成時，下一次巡邏會直接跳過，避免重複處理同一支影片。 

let isProcessingQueue = false;

async function processQueuedVideos() {
  if (isProcessingQueue) {
    log("上一輪還在跑，跳過這次巡邏");
    return;
  }
  isProcessingQueue = true;
  try {
    await processQueuedVideosInner();   // 真正的處理邏輯
  } finally {
    isProcessingQueue = false;
  }
}

成本是一行旗標。省下來的是每支長片重複的一次下載、加上兩次 LLM 呼叫的費用。這個 bug 最早就是在「一次重跑三支」時被一支長片觸發、白花了一次處理費才抓到的。

# 成果：EP182 整理前後的章節重組

把規則套回 EP182 重跑一次，整理的章節組織明顯變清楚。下面是同一支影片、舊版與新版的章節對照：

章 舊版 新版
1 犯罪動機：情殺、仇殺、財殺 犯罪動機的三大類型：情殺、仇殺、財殺
2 無差別犯罪與模仿犯：鄭捷案分析 無差別犯罪與模仿效應：以鄭捷案為例
3 病理根源：日本少年A 案例與犯罪基因探討 犯罪基因與先天傾向：戰士基因、XYY、快樂殺人
4 認知扭曲：敵意、神經質與合理化 導向犯罪的心理特質：神經質、敵意、扭曲的認知
5 修復式司法與犯罪的社會代價 犯罪如何養成：小嘗試累積、正增強與精算心態
6 理性精算與人性本善本惡之辯 修復式司法與被害者視角
7 結語與對談感想（寒暄） 人性本善還是本惡：自我與他人之間的平衡

對照上面兩版的章節結構，新版做了兩件事。其一，把原本綁在同一章的兩個獨立主題拆開，各自成章，讀起來像兩個各自成立的主題，避免無意間暗示因果。其二，把結尾原本用來寒暄的一章換成實質討論，把一格位置還給內容。整體讀下來，每一章都對應一個站得住的主題。

需要澄清的是：兩個版本在事實層面均無問題，差異僅在於章節的組織方式。這一輪真正的改善在把關流程——讓「摘要沒有亂編」從一句自我宣稱，變成一份可以對著逐字稿逐句查證的清單。

驗證的目的在於確認輸出內容的可靠性，並標示需要進一步人工查證的部分。通用規則、逐字稿對照、跨類型樣本，三件事合起來，讓「這份整理忠於原文」成為查得到的事實。
