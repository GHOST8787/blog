補上 Chrome 同步分頁的操作缺口：
Device Tabs Opener

Engineering Chrome Extension Open Source
2026.04.20 BY GHOST_1010

一支解決「從其他裝置批次開啟分頁」需求的 Chrome Extension。涵蓋 Manifest V3、Vanilla JS 實作、MIT 開源授權與 Web Store 上架流程紀錄。

诶嘿

Chrome Extension 是裝在 Chrome 瀏覽器上的小型外掛程式，安裝後在工具列出現一個圖示，點開就能執行特定功能。本專案的功能是把手機 Chrome 上開著的分頁，按一個按鈕全部開到桌面瀏覽器繼續看。Manifest V3 是 Chrome 自 2024 年起對新上架擴充功能要求的技術規範，本專案依此規範開發、走完 Chrome Web Store 審核並上架。

# 問題：功能存在，但操作路徑破碎

Chrome 的跨裝置同步分頁功能，會自動將 iPhone / iPad 上的開啟分頁同步至桌面端。存取路徑為：

Chrome → 歷史記錄 → 從其他裝置開啟的分頁

然而，此清單僅支援逐筆點擊開啟。若有 10 個待處理分頁，需重複操作 10 次，且每次點擊後焦點跳離清單，需再次返回。對於「將手機上累積的所有分頁一次開到桌面環境」的使用場景，操作成本偏高。

Chrome 已實作同步功能本身。缺少的是「批次操作」的介面環節。

# 實作：三支 API 拼湊的最小閉環

技術棧選擇

  • Manifest V3：Chrome 自 2024 年起要求新上架擴充功能採用 V3 規範，以 Service Worker（背景常駐的輕量化程序，需要時才喚醒、不用時自動休眠以節省記憶體）取代舊版常駐型的 Background Page，整體權限模型更嚴格。
  • Vanilla JavaScript：原生 JavaScript，不使用 React、Vue 等前端框架，也不引入打包工具。整體為單一 HTML + 單一 JS 檔案，約數百行。功能規模單純的工具型擴充採用此選擇可降低依賴與維護成本。

目錄結構： 

device-tabs-opener/
├── manifest.json     # 權限與入口宣告
├── popup.html        # 點擊工具列圖示之 UI
├── popup.js          # 互動邏輯與批次開啟實作
├── background.js     # Service Worker（V3 必要）
└── icons/            # 工具列圖示

核心 API

API 用途
chrome.sessions.getDevices() 讀取所有同步裝置及其分頁清單，回傳結構化物件（裝置名、標題、URL、最後使用時間）
chrome.windows.create({ url: [...] }) 將 URL 陣列一次性開啟至新視窗。選擇新視窗而非現有視窗，是為了避免一次塞入大量分頁打亂既有工作流程
popup UI 列出所有裝置與分頁，每筆附 checkbox，提供「全選」「取消全選」「開啟選取的分頁」三顆按鈕

從點擊圖示到新視窗開啟所有選取分頁，約 2–3 秒。

權限與隱私宣告

manifest.json 僅宣告兩個權限：

  • sessions：讀取其他裝置同步之分頁清單
  • tabs：在新視窗中開啟選取的分頁

未使用 storage、activeTab、host_permissions。所有資料於本機處理，執行完即丟，無後端、無第三方追蹤、不收集使用者資料。原始碼公開於 GitHub，MIT 授權。

# 上架流程紀錄

這是第一次完整走完 Chrome Extension 從開發到上架的流程。以下為關鍵節點：

1. 授權選擇：MIT

考量為個人工具且期望他人可自由 fork 修改，選擇條件寬鬆的 MIT 授權 — 保留著作權聲明後，可商用、修改、再散布。

2. Chrome Web Store 開發者帳號

一次性 5 美元註冊費，完成後即可建立擴充功能。

3. 打包與素材準備

將目錄壓縮為 .zip 上傳。需額外準備：

  • 擴充圖示（128×128）
  • 宣傳圖（440×280）
  • 商品截圖（1280×800）
  • 商品描述與權限用途說明

素材準備耗時最長，程式碼反而早已完成。

4. 審核

功能單一、權限合理、無額外蒐集行為 — 一次通過。僅需等待審核排隊。

5. 上架後安裝體驗

使用者可從 Chrome Web Store 直接點擊「加到 Chrome」，無需開發者模式或下載 zip。

# 對使用者的意義

  • 直接解決原本的多次點擊負擔 — 10 個待處理分頁從「逐筆點 10 次」壓縮到「點圖示、全選、開啟」三步驟，約 2–3 秒。
  • 補上原生功能的缺口 — Chrome 早已實作跨裝置分頁同步，本擴充補上「批次操作」的最後一哩，避免使用者另外去找協作工具或第三方服務。
  • 最小權限可信 — 僅宣告 sessions 與 tabs 兩個權限、無後端、無資料上傳、原始碼開源並採 MIT 授權，使用者可自行檢視程式碼確認無隱私疑慮。
