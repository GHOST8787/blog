海科館生物資料庫：
拿現在的資料庫視角，回看當年那疊 Excel

Engineering Database Data Modeling
2023.09 — 2024.03 BY GHOST_1010

國立海洋科技博物館內部生物資料庫的整理工作。當年交付的是統一的缸體編碼、清乾淨的物種清冊，以及一疊 Excel 樞紐報表。本文以現在的資料庫設計視角回顧，將當年散落的 Excel 檔案重新整理，分析其資料架構，並提出一版重做的關聯式設計方案。

# 當年手上的資料，長這樣

所有東西都在 Excel 裡，分散在六份以上的活頁簿，每份底下再開十幾個工作表。同一批物種資料，在不同檔案裡以不同欄位、不同編號重複出現。

缸子清冊
缸位主表。欄位：No. / 新編碼 / 舊名 / 說明。負責把每一缸的新編碼對回原本的口語舊名。
生物盤點表
按展示區拆成多個工作表。欄位：缸體編號 / 中文名 / 俗名 / 學名 / 屬 / 科 / 目 / 數量 / 有無照片。
未拍物種總和表
追蹤哪些物種還沒有影像紀錄。欄位：展示區域 / 中文名 / 缺少的照片學名。
養殖系統日報表
一個月一個檔，一天一個工作表。記缸體清潔（換水 / 抽底 / 濾袋 / 視窗 / 蛋白）、生物狀況、機電、水質十二項。
月度統計樞紐
按月切的死亡 / 移缸統計。欄位：目 / 科 / 屬 / 中文名 / 學名 / 數量 / 區域 / 缸體編號，外加一組樞紐欄。
生物總整理
把各區盤點併成一張總表，供樞紐分析。物種數量與隻數在這裡各版本略有出入。

# 當年的資料流

把六份檔案的關係畫出來，實際的流向是這樣：多個來源匯進人工整合，整合後再手動生出清冊與樞紐報表。整合過程完全依賴人工操作。

來源層
缸子清冊 生物盤點表 養殖日報表 未拍物種表
整合層（人工）
統一缸體編碼 · 手動對齊欄位 · 消重複 · Excel 樞紐分析
產出層
統一物種清冊 月度死亡 / 移缸統計 未拍物種清單

# 缸體編碼 schema

整合的第一步是重編缸號，讓散落在不同名稱、不同尺寸的缸位能被統一索引。範例 C0AP0108L31（舊名「A中3-1」，108 公升），拆解如下：

段 範例值 意義
類型字元 C0 / A1 / A2 / A3 / A4 主缸類型（如 A1 大池、A2 主題缸、A3 水母、A4 中型主題、C0 後場標準缸）
區域 A / B / C 後場分區（A 區、B 區、C 區）
尺寸代碼 P / F / T 等 缸型分類（標準矩形 / 圓筒 / 噸級主缸）
水體量 0108 / 0320 / 0150T 公升（L）；噸級主缸用 T 後綴（如 0150T = 150 噸，見大洋池 A1NN0150T01）
序號 L31 / L01 ... 同尺寸同區域內的流水序號

# 從那疊 Excel 裡，其實藏著這些實體

把重複的欄位對齊、把散落的工作表併回去，會發現當年的資料其實描述了幾個很清楚的實體。它們之間本來就有關聯，只是被 Excel 的平面格子壓扁了：

關聯很單純：一個缸位有很多筆在缸紀錄、很多筆日誌、很多筆水質、很多筆事件；一個物種可以出現在很多缸位。缸位與物種是多對多，中間靠「在缸」這張表接起來。

# 當年這套架構的幾個痛點

用現在的眼光看，當年的資料有幾個地方會讓後續維運很痛。這些問題是 Excel 作為資料載體在規模擴大後的必然限制：

同一份資料散在六份檔案

物種清單在盤點表、總整理、月度統計裡各存一份。改一個學名要追著改三個地方，版本一不同步就對不起來。

缸體編碼存在多個版本

清冊裡同時有四碼與三碼兩套編法（A1NN0150T01 與 A1N0150T01）。同一缸兩種寫法，交叉比對就會漏。

日報一天開一個工作表

一個月就是三十一個結構相同的分頁。要看一缸整季的趨勢，得手動翻九十幾個分頁再貼進樞紐。

死亡與移缸藏在自由文字裡

生物管理欄寫的是「食慾佳，移入 A 中 4 龍虎斑 *4」這種句子。要統計月死亡數，只能靠人一句一句讀出來再手動加總。

水質橫向展開到三百多欄

每個缸的十二項水質沿著欄位一路往右鋪，一張表寬到三百多欄。新增缸位時需修改整張表的結構。

# 如果現在重做：一版關聯式設計

把上面那些實體落成正規化的資料表，痛點將逐一解決。核心是一個原則：每個事實只存一次，其他地方用外鍵指過來。

資料表 解掉的痛點
tanks 缸位只有一張主表，編碼定一套。舊名放 legacy_name 欄，查得到也不會混。
species 物種只存一次。改學名改一個地方，全站跟著對。
stock 缸位與物種的多對多用一張連接表處理，一缸幾種、一種在哪幾缸都是一句查詢。
daily_logs 日誌改成一列一天一缸，日期是欄位。整季趨勢用日期範圍撈，不再翻分頁。
water_quality 水質改成長格式，一列是一缸一次的量測。加缸只是多幾列，不動結構。
events 死亡 / 移入 / 用藥拆成有 type 欄的結構化事件。月度死亡統計僅需一條 group by 查詢即可完成。

最有感的一項是 events。當年要生月度死亡統計，得把一整個月的日報一句一句讀過去、人工挑出死亡再加總。換成事件表以後，同一份報表退化成一句查詢：select species_id, sum(qty) from events where type='死亡' and month=…。管理水族館的資料與管理缸內生物息息相關，核心在於讓狀態清晰可見，並能追溯所有變動。
