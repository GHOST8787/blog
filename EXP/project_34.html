LINE 電腦版圖片與檔案傳不出去
IPv4、IPv6 與熱點的 IPv6 斷路

熱點的 IPv6 有位址、連不到外網，LINE 電腦版的圖片和檔案因此送不出去；關掉 Wi-Fi 的 IPv6 後，連線時間從 106 秒降到 1.2 秒。

Engineering Network Debug
2026.11.17 BY GHOST_1010

筆電接手機熱點後，LINE 電腦版的文字訊息傳得出去，圖片和檔案一直轉圈送不出去。原因是熱點配發了 IPv6 位址，IPv6 卻完全連不到外面，LINE 新開的連線先在 IPv6 上等到逾時才改走 IPv4。關掉 Wi-Fi 的 IPv6 之後，連到 LINE 伺服器的時間從 106 秒降到 1.2 秒。

# 症狀

LINE 開得起來，聊天室和歷史訊息都看得到，打字的訊息也送得出去。只有圖片和檔案，按下送出就停在轉圈。同一時間瀏覽器開網頁、看影片都順，Wi-Fi 顯示已連線，閘道和公用 DNS 都有回應。

遇到這個狀況，第一步是上網搜尋。搜到的說法大多是「LINE 要更新」。

# 排查流程

LINE 的更新紀錄顯示已是最新版 26.6.0.4004，更新這條路走不通。接下來從 LINE 往下一層一層查，每一步的結果決定下一步查哪裡。

01
伺服器連得到嗎
看到 連 gw.line.naver.jp：連上了，走 IPv4，花了 106 秒。DNS 回的位址 IPv6 排前面。
所以 伺服器沒掛，問題是「慢」。先查是不是整條網路都慢。
02
整條網路慢嗎
看到 熱點閘道、公用 DNS 都秒回，網頁影片正常。
所以 IPv4 沒問題。最後成功的是 IPv4，106 秒就花在它前面試的 IPv6 上。
03
IPv6 通不通
看到 筆電有 2 個 IPv6 位址和預設路由，系統會先試 IPv6。curl 強制走 IPv6 連 LINE，15 秒逾時。
所以 106 秒＝在 IPv6 上等逾時。還要分清是 LINE 那端還是我這端。
04
LINE 那端還是我這端
看到 換 Google、Cloudflare，Cloudflare 直接打 IP 排除 DNS，IPv6 全部不通。
所以 幾家大站不會同時掛，壞的是熱點的 IPv6。不用這條 IPv6 就好。
05
修完怎麼確認
看到 關掉 Wi-Fi 的 IPv6，重跑第 1 步同一個測試：106 秒降到 1.2 秒，LINE 全走 IPv4，網速正常。
所以 用同一把尺量前後，數字對得上才算修好。

# IPv4 與 IPv6

網路上每台設備都要有一個位址，封包才知道要送去哪裡。IPv4 是用了四十多年的版本，位址長度 32 位元，寫成 203.0.113.25 這種四段數字，總共約 43 億個。上網的設備早就超過這個數量，負責發放位址的 IANA 在 2011 年 2 月把最後一批 IPv4 位址區塊分配完畢。

IPv6 是接班的版本，位址拉長到 128 位元，寫成 2001:db8::1 這種冒號分隔的十六進位，數量大到每台設備都能分到自己的公開位址。

項目 IPv4 IPv6
位址長度32 位元128 位元
寫法203.0.113.252001:db8::1
位址數量232，約 43 億2128，約 3.4 × 1038
預設優先權（RFC 6724）3540
DNS 記錄AAAAA

兩種位址目前並存。一台電腦可以同時拿到 IPv4 和 IPv6，一個網域也可以同時登記兩種位址。程式連線前先問 DNS，DNS 把兩種位址都交回來，接下來由作業系統排先後。

小知識：電腦為什麼先連 IPv6

排先後的規則寫在 RFC 6724，裡面有一張「優先權表」，數字大的先試。一般的 IPv6 位址（表裡寫成 ::/0）是 40，IPv4 位址（表裡寫成 ::ffff:0:0/96）是 35。40 比 35 大，所以 IPv6 排前面。Windows 用 netsh interface ipv6 show prefixpolicies 看得到自己這張表，數字跟 RFC 一樣。

這張表只看「位址的種類」，不看「這條路現在通不通」。電腦只要手上有一個看起來正常的 IPv6 公開位址，就認定 IPv6 可用，排到前面去試。熱點的問題就出在這裡：位址發了、路由也發了，表上一切合格，封包卻出不去。

小知識：IPv4 發完了為什麼還能用

靠 NAT（網路位址轉換）。家裡的路由器只向電信業者拿一個公開 IPv4 位址，屋內的手機、筆電、電視各拿一個 192.168.x.x 這種內部位址，出門時由路由器換成同一個公開位址，回來再對回是誰的。手機上網也一樣，電信業者在機房再做一層，讓很多支手機共用一個公開位址。所以 IPv4 撐得下去，代價是設備之間沒辦法直接互連，要靠路由器轉手。IPv6 的位址夠每台設備各分一個，不需要這一層轉換。

# 病根：有位址、出不去的 IPv6

熱點是一支 Galaxy A22 5G，它發得出 IPv6 位址，接不通 IPv6 的外部網路。LINE 照著排序先連 IPv6。用 Get-NetTCPConnection 看當下的連線，有兩條停在 SynSent：連線請求送出去了，對方一直沒回。一條連向 LINE 自己的 2400:dcc0:a3a1:1000::5，一條連向 AWS CloudFront。同一時間 LINE 另有一條連線早就用 IPv4 建好，文字訊息走那條，所以照常送出；傳圖片和檔案要另外開新連線，新連線照排序先試 IPv6，就卡在這兩條上。

Windows 的做法是一個位址一個位址試，每個都等到逾時才換下一個，IPv6 全部試完才輪到 IPv4，流程圖第 1 步量到的 106 秒就是這樣累積出來的。連線測試最後顯示成功，只看結果欄會以為網路正常，耗掉的時間要另外量才看得到。

為什麼瀏覽器沒事

瀏覽器和 curl 實作了 Happy Eyeballs（RFC 8305）：IPv6 起跑後很短的時間內沒回應，就同時開一條 IPv4，誰先連上用誰。IPv6 壞掉時使用者幾乎感覺不到。逐一嘗試、每個位址都等到逾時的程式，才會整個卡住。

同一種病在家裡的 HiNet 也出現過。Python 寫的直播偵測程式打 youtube.com 每個請求固定卡約 168 秒，DNS 回了 8 個 IPv6 位址，每個逾時約 21 秒，8 × 21 = 168，全部燒完才輪到 IPv4。當時 curl 打同一個網址只要 0.3 到 0.8 秒，差點就判成「YouTube 在限速」。

# 自己判斷的三個指令

網路測速正常、只有某些軟體卡住時，在 PowerShell 照順序跑這三步，就能確認是不是同一個原因。

1 — 網域有沒有 IPv6 位址

Resolve-DnsName gw.line.naver.jp -Type AAAA

有查到 AAAA 記錄，代表這個軟體可能先試 IPv6。

2 — 強制只走 IPv6 會不會通

curl.exe -6 -m 15 -s -o NUL -w "%{time_connect}`n" https://www.google.com
curl.exe -4 -m 15 -s -o NUL -w "%{time_connect}`n" https://www.google.com

-4 秒回、-6 逾時，就是 IPv6 對外不通。換 Google、Cloudflare 多測幾個網站，全部逾時就能排除單一網站的問題。

3 — 軟體有沒有卡在半路的連線

Get-NetTCPConnection -State SynSent -OwningProcess (Get-Process LINE).Id

列出來的遠端位址帶冒號，就是卡在 IPv6 上的連線。

# 修法與代價

筆電這邊直接把 Wi-Fi 網卡的 IPv6 拿掉，要用系統管理員身分執行： 

# 關閉
Disable-NetAdapterBinding -Name 'Wi-Fi' -ComponentID ms_tcpip6

# 之後要恢復
Enable-NetAdapterBinding -Name 'Wi-Fi' -ComponentID ms_tcpip6

這個設定綁在網卡上，對之後連上的每一個 Wi-Fi 都生效，重開機也會保留。代價是 IPv6 真的通的網路也一起用不到 IPv6，目前大部分服務都同時提供 IPv4，日常使用感覺不到差別。網卡名稱用 Get-NetAdapter 查，筆電上通常叫 Wi-Fi。

事後查微軟的說明文件，官方不建議把 IPv6 從網卡拿掉，原因是部分 Windows 元件內部會用到 IPv6，拿掉後可能不正常。官方建議的做法是保留 IPv6、改成「優先 IPv4」：把登錄檔裡的 DisabledComponents 設成 0x20，重新開機後生效。效果等於把上面那張優先權表的 IPv4 調到 IPv6 前面，程式一樣先試 IPv4，IPv6 留著當備用。 

# 系統管理員身分執行，之後重新開機
$key = 'HKLM:\SYSTEM\CurrentControlSet\Services\Tcpip6\Parameters'
New-ItemProperty -Path $key -Name DisabledComponents `
    -PropertyType DWord -Value 0x20 -Force

自己寫的程式可以只動自己。Python 把 socket.getaddrinfo 包一層，只留 IPv4 的結果、查不到 IPv4 時退回原結果，整台電腦的設定不用動。前面那支直播偵測程式就是這樣修的，請求時間從 168 秒降到 0.15 秒。

# 解決之後

關掉 IPv6 是止血，留下三件事。第一，這台筆電現在連任何 Wi-Fi 都只走 IPv4。之後如果用到 IPv6 才有的服務，或是要做 IPv6 相關的開發測試，要記得先執行上面的恢復指令。

第二，比較穩的長期做法是換成微軟建議的「優先 IPv4」。熱點的 IPv6 一樣是壞的，程式會先走 IPv4、不碰到它；換到 IPv6 正常的網路時，IPv6 還在，需要時仍然用得到。

第三，熱點和 HiNet 的 IPv6 為什麼連不出去，這次沒有找電信業者追。換一個新網路時，用「自己判斷的三個指令」的第 2 步跑一次 curl -6，秒回就代表這個網路的 IPv6 是通的。

下次遇到「網路測速正常、某個軟體只有部分功能卡住」，可以考慮量測它要連的網域走 IPv4 和 IPv6 各要多久，比重灌軟體快得多。
